# 活动互评功能与运营说明

本功能为同一活动中实际到场的玩家收集体验评分、文字评价和独立举报，作为将来合拍分数的数据来源。当前版本完成数据采集和审核，不计算综合合拍分数，不将新评分写入旧互评表或匹配算法。

本文记录当前仓库实现、后台操作方式和验证边界。代码、迁移文件或本地测试存在，不代表 Production 已完成迁移、应用发布或真实账号验收；上线结果以相应发布记录为准。

## 功能范围

| 项目 | 当前行为 |
|---|---|
| 评分对象 | 管理员确认的本轮活动到场名册，排除自己；不要求对方是旧匹配搭档 |
| 身份确认 | 同时显示姓名和昵称，可按姓名或昵称检索；业务关系始终使用成员 ID |
| 体验评分 | 单一 1–5 分，0.5 分刻度，共九档；新评价没有预填默认分数 |
| 文字评价 | 可选，最多 500 个字符 |
| 评分修改 | 开放时间内可修改本人已提交评分和评论，保留版本历史；截止、暂停或评分被标记无效后不能修改 |
| 举报入口 | 红色感叹号与文字按钮，先确认被举报玩家，再展开举报表单；确认弹窗本身不会提交举报 |
| 举报内容 | 骚扰或不当接触、隐私问题、干扰活动、其他；具体说明为 10–2000 个字符 |
| 评分与举报 | 可只提交评分、只举报，或一起提交；一起提交时使用同一数据库事务 |
| 举报修改 | 待处理时可修改本人举报类型和正文，后台保留修改前后内容；处理中、已处理或已关闭时通过补充或更正提交，最多 50 条补充，重新进入待处理状态 |
| 开放条件 | 管理员独立启用、确认名册，且当前时间处于开放时间内；与报名开放状态分开 |
| 截止后举报 | 本场互评曾实际开放，且双方仍符合参与资格时，暂停或评分截止后仍可举报及补充 |
| 展示范围 | 玩家只看自己提交的评分、评论、举报和举报状态；看不到别人给自己的逐条评价或举报 |
| 当前客户端 | Web Player 和 Web Admin；微信小程序继续保留旧互评链路，本次不宣称同步上线 |

“报名成功”与“已确认到场”分开处理。未取消报名名单只用于管理员预选；管理员可以移除缺席者，并为临时到场的现有成员补录。补录不创建账号，不自动补写报名，也不绕过账号及成员资格检查。

## 页面与入口

| 页面路径 | 更新内容 |
|---|---|
| `/app` | 仅提醒开放且本人尚未提交过评分或举报的活动；提交过任一条后取消该场角标和优先提醒，常驻入口仍指向参与记录 |
| `/app/matches#participation` | 活动参与卡显示互评入口、已评价数量和开放状态；开放互评的历史活动继续便于访问 |
| `/app/matches/rounds/[roundId]` | 既有报名记录详情接入活动互评入口 |
| `/app/matches/rounds/[roundId]/reviews` | 参与者检索、九档评分、文字评价、举报确认；“我的评价与举报”显示授权姓名与昵称，可直接修改评价、修改待处理举报或补充更正 |
| `/admin/activity-reviews` | 新增活动选择、概览、开放设置、参与名册、评分记录、举报处理和操作历史 |
| `/admin/matching/rounds/[id]` | 普通活动报名轮次显示活动互评概览及管理入口 |
| `/admin/members/[id]?tab=activity` | 成员 360 显示活动互评说明；超级管理员可进入按该成员筛选的互评后台 |
| 后台主导航 | 运营区新增“活动互评” |

活动互评后台使用 `roundId` 选择活动；从成员 360 进入时附带 `memberId`，仅筛选本活动中与该成员有关的评分和举报。后台可切换其他活动继续查看。成员 360 本身不展示举报人、举报原文或内部审核说明。

参与记录组件被其他页面复用时保持现有接口兼容；本次明确接入的玩家页面为上表中的首页、参与记录和轮次详情。旧 `/app/reviews/new/[id]` 和旧匹配详情仍属于搭档互评。

## 提交后的查看与修改

首页角标只统计目前可评价、且本人从未提交过该场评分或举报的活动。成功提交任意一条评分（文字选填）或单独举报后，该场不再计入角标，也不再占用首页优先提醒。既有提交直接适用；活动暂停后重开不会重复提醒已提交者。“活动互评”常驻入口保留，玩家仍可继续评价实际交流过的其他人。

“我的评价与举报”按玩家显示自己的评分、评论、举报、处理状态和更新时间，不展示对象编号或当前版本。授权范围内显示姓名及昵称；身份不可见时显示“玩家信息暂不可用”。历史对象信息与操作权限由数据库独立返回，不受上方搜索条件或名单分页影响，也不扩大取消报名、移出名册或匿名化后的身份可见范围。

点击记录中的“修改评价”或“修改举报”打开编辑弹窗，自动带入保存值。取消不会保存，成功后原记录即时更新。评分和举报独立提交，修改不增加记录条数；提交中不能关闭弹窗或切换对象。评分仍只在开放窗口且评价有效时可修改。历史评价改为 1.0 分时，也会在确认后展开举报表单；此处仅提交举报会保留评价编辑器和未保存评分，避免误报为评价已更新。

待处理举报可修改类型和正文，保留创建时间与原有补充，并在后台记录修改前后内容。处理中、已处理及已关闭的举报通过“补充或更正”追加说明，原内容保留，提交后回到待处理。举报修改和补充都遵守双方参与资格与本场曾开放的条件；评分截止不会单独关闭举报渠道。修改举报与管理员处理同时发生时，旧版本提交被拒绝，玩家输入保留并提示刷新。

2026 年 10 月 3 日此次调整的前后截图及验证范围见 [历史记录更新审查](../reviews/activity-peer-reviews/history-update/README.md)。

## 与旧评分的区别

旧 `public.mutual_reviews` 绑定匹配搭档或同组成员，使用五个整数评分维度，并通过触发器更新 `member_dynamic_stats`。匹配算法还会将旧互评的 1 分解释为双方不再匹配，将双 5 分纳入冷却及重逢规则。

新功能使用独立的 `private.round_peer_reviews`、`private.round_peer_reports`、`private.round_peer_review_settings`、`private.round_peer_review_participants` 和 `private.round_peer_review_audit`。新评分不会触发旧互评统计，也不写入个人主页的综合合拍指标。

- 评分控件为原生拖动条，范围 1.0–5.0、步进 0.5；未操作时保持未评分。鼠标、触摸及键盘共用同一数值。
- 在玩家界面保存 1.0 分时，先显示恶意行为与举报提示；确定只展开表单，不发送请求。1.0 分状态下提交评分与举报、仅举报或补充时，再确认人工审查提示。取消保留草稿。其他分数沿用原流程。
- 1.0 分评分须经合并入口与举报一起提交；已有举报时填写补充，用现有原子接口同时保存评分、追加说明并进入待处理，保留原内容及版本冲突保护。仅提交举报或补充不保存评分、评论。
- 以上是玩家界面引导，不新增数据库触发器或改变 RPC 的评分规则，不自动拉黑或处罚成员。举报继续进入原有管理员审核流程。
- 举报是单独提交和审核的业务记录，可以不附带评分。
- 5 分不自动触发再次匹配。
- 标记评分无效不删除原文；恢复有效需要重新检查参与资格。
- 本期不提供排行榜、评分公开、权重公式、反向推断评价人或自动处分。

旧《合拍分数制度》中“整数”“1 分必定举报”等规则不能直接套用到本功能。后续若将本批数据用于综合合拍分数，应另行确定来源版本、有效样本、重复活动权重、最小展示样本量及公开方式。

## 管理员首次开放流程

普通管理员与超级管理员均可通过活动互评后台管理本功能；每个数据库写入 RPC 都重复校验管理员身份。成员生命周期等既有高风险操作继续使用原有权限边界。

1. 在“活动互评”选择正确轮次，核对活动名称。
2. 先填写开放和截止时间，保持“启用本场活动互评”关闭，填写 4–500 字理由并保存。首次保存建立版本 1 的设置。
3. 在“确认活动参与名册”逐个核对实际到场玩家。未取消报名会预选，缺席者应取消勾选；同名者用昵称复核。
4. 临时到场者从“补录实际到场成员”搜索已有成员后加入。填写名册确认理由，说明实际到场核对和补录、移除情况。名册至少需要两人。
5. 保存确认名册，等待页面读取新的设置版本。
6. 回到开放设置，开启“启用本场活动互评”，填写本次开放理由并保存。若开始时间尚未到达，页面显示待开放；实际写入仍由数据库时间判断。

所有后台日期输入及时间展示使用日本时间 `Asia/Tokyo`。数据库使用带时区时间戳，开放区间为“包含开始时刻，不包含截止时刻”。用户设备时间不能绕过后台校验。

“未开放、待开放、开放中、已暂停、已截止”是从启用开关、名册和时间派生的状态。暂停使用独立启用开关；到截止时间自动停止评分写入。要延长或重新开放，应明确修改时间及启用状态并记录理由，不能通过重新开放报名代替。

## 名册调整

后台显示确认参与人数、评分记录数、已参与评价人数和待处理举报数。名册可再次确认，每次保存都会更新配置版本并记录审计。

从名册移除玩家会保留全部历史记录，并将其作为评价人或被评价人的既有有效评分标记无效。重新加入名册不会自动恢复这些评分，管理员需逐条审核后恢复。举报历史不会因普通名册调整而删除。

玩家账号被关闭、未批准、不是当前玩家身份、已匿名化或已取消本轮报名等情况，会在读取或写入时重新检查，不因早先进入名册而永久获得权限。实际到场的补录成员仍必须是已存在且符合条件的成员；明确取消报名的账号应先按报名规则处理其状态。

参与名单、评分对象、名册是否已确认均由服务端判断。修改浏览器里的成员 ID 或直接调用接口不能使跨活动、自评或未入名册的请求通过。

## 评分与举报审核

评分记录支持按评价人、被评人、昵称及评论内容检索，并按有效性筛选和分页。目前后台在授权后取得本轮完整上下文，先筛选再分页；玩家端的参与者检索与分页在数据库进行，不能通过当前页筛选漏掉其他参与者。

评分审核选择“有效”或“无效”，必须填写 4–500 字理由。它改变的是有效性，不替玩家改分或重写原评论。审核前后版本可在该记录的处理历史查看。

举报状态为待处理 `pending`、核查中 `reviewing`、已处理 `resolved`、已驳回 `dismissed`。每次保存需提供 4–2000 字内部处理说明和 4–500 字操作理由。玩家只看到处理状态及自己提交的举报、补充，收到的响应不包含内部处理说明或管理员审核原始数据。

举报内容、补充和处理历史仅供本人及获授权管理员查看，修改前后审计与内部处理说明仅在后台展示。每份举报最多保留 50 条补充，达到上限后不能继续追加，也不会覆盖已有内容。历史操作显示中文名称，并区分玩家、管理员与系统操作。审核并不自动拉黑、禁言或关闭账号；若核查后需要采取其他措施，应通过相应管理模块按其既有权限及理由要求操作。

## 隐私与数据生命周期

私有表不向匿名或普通登录角色授予直接读写权限，并启用 RLS。公开 RPC 采用明确的执行权限白名单、固定 `search_path` 和函数内部身份校验；允许调用某个 RPC 不等于能访问任意玩家的数据。

玩家响应只包含本人写出的评分和举报，不返回别人对自己的原始记录。举报内容不混入评论字段，也不依赖前端折叠来保护。中文、日文界面使用同一权限和长度限制。

新业务关系已加入成员生命周期预检的计数。存在新参与、评分、举报或审计数据的成员不能被当成无业务记录外壳硬删除，原有生命周期预检和超级管理员限制继续保留。

成员匿名化时，关联评分评论被清空并标记无效；举报原文、补充、内部备注被清空；相关审计快照、自由文本和请求重试负载被清理；名册移除该成员。保留的结构和统计关系用于审计，不等于保留原个人文本。不得为了重试写入而重新填回已匿名化的内容。

## 并发修改与重试

设置和名册共用 `settings.version`；评分、举报分别拥有独立版本。后台及玩家写入均携带读取时的 `expectedVersion`。如果另一位管理员或玩家已保存，旧页面提交返回版本冲突，不覆盖新记录。

后台遇到冲突会保留当前输入并显示中文提示。应先记录自己尚未保存的内容，刷新核对最新状态，再按实际差异重新提交。不要绕过版本检查改为无条件写入。

玩家同一次评分或举报提交使用稳定请求 ID；网络失败后以相同内容重试可返回原结果。更换内容后重新生成请求 ID。组合提交采用原子事务，不能出现评分已成功、举报失败却提示整体成功的状态。

后台表单阻止重复点击，并对未保存内容提供离开提醒。多个管理表单同时编辑时，保存一个表单前会提醒其他未保存内容可能在刷新后丢失；建议一次完成一项操作。该提示与数据库版本检查分别保护本地输入和服务端记录。

## 秋季迎新派对配置指南

本次确认的正式活动时间为 **2026 年 10 月 10 日 13:00 至 10 月 11 日 17:00，日本时间**。当前仍处于报名阶段。互评的到场名单尚不应被当成最终名单，本文也不表示已经在真实轮次上写入或启用了任何互评设置。

1. 发布后先从轮次详情的“管理活动互评”进入，核对确为“秋季迎新派对”，避免依据相似名称选错轮次。
2. 可以提前以关闭状态保存拟定互评时间。建议以 10 月 11 日 17:00 活动结束后作为开放起点；如实际结束或人员确认延迟，使用实际可开放时间。
3. 截止时间由运营决定。例如可选 10 月 18 日 23:59 日本时间，作为活动后集中收集的一次安排；这只是配置建议，不是已写入的默认值。
4. 活动当天根据签到或工作人员核对结果确认名册，移除取消、缺席或不符合条件的账号，补录确实到场且已有有效账号的成员。
5. 名册确认完成后再启用互评，并用一名实际符合条件的玩家验证入口和可见名单；不要给真实玩家写入测试评价。
6. 首轮收集期间重点观察无法找到对象、同名误选、重复提交、截止冲突和举报积压。需要暂停时关闭互评开关，保留历史数据。
7. 到期检查评分关闭、本人历史仍可读、符合条件者仍可通过独立举报流程反映情况。延期必须通过设置并填写理由。

若希望 10 月 10 日第一天活动后就开始收集，应由运营明确分批确认到场和提前开放的安排；不要因报名已经开放而自动允许提前评价。
