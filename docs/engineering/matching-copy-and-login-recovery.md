# 匹配文案与登录失效恢复

本次只实施已确认的四项：精简玩家匹配相关中日文、隐藏后台方案名、纠正已发布方案的取消池提示、完善登录失效提示和返回原页。普通退出登录仍沿用原范围，不新增跨登录草稿保存或自动提交。

## 玩家看到的内容

- 提交成功只确认时间与偏好已保存，引导查看站内通知及“匹配”，不承诺截止后才安排、一定匹配或绝对最佳。
- 报名记录保留已保存答案和现有状态，移除活动次数统计口径说明。
- 有轮次的匹配结果只显示轮次名称；状态卡不显示后台方案名。无轮次的历史独立结果保留原标题兼容。
- 匹配通知在读取层使用统一中日文，按实际轮次公开名称显示；缺少轮次时使用通用内容，不回退到可能含后台方案名的旧通知原文。
- 通知发送、所有权、已读、过期、失效链接和发布保护保持原样。数据库既有通知原文不回写，不需要迁移。

## 后台取消池

仅当方案有轮次、状态为草稿且结果已就绪时，读取人工配对与取消池资格预览。已发布和生成中跳过要求草稿的预览：保留区域与按钮位置，说明先撤回或等待生成，禁用操作，不显示不可信人数或成员。真正读取失败才提示重试；撤回后按原规则恢复预览。

不修改资格、评分、取消池、重开、冷却、导入、发布或替换规则，不放宽数据库限制。

## 登录失效恢复

代理覆盖内部返回路径及会话存在提示，保留原 Player App 路径与业务查询参数，剔除 Next.js 的 `_rsc` 参数。会话存在提示只控制文案，不参与身份或权限判断。

原鉴权已确认无可用用户后，登录跳转携带经过严格校验的站内 `/app` 返回路径；曾有本站会话时，登录页原说明位置显示失效提示。有效续期继续静默；网络、429、5xx 等临时失败继续使用既有可重试处理，不当成强制退出。

密码登录、社交登录及回调复用安全返回路径；会员审核、停用与资料补全路由仍先按原生命周期执行。报名及资料补全的错误处理保留 Next.js 跳转控制流，不能把它误报为普通网络失败。

SDK 既有失效 Cookie 清理和代理写回保持。普通退出范围、登录入口和界面布局不变；不自动重提报名。返回原页面不代表恢复未提交答案。

## 验证边界

针对测试覆盖中日文及旧通知显示、轮次标题与历史兼容、真实详情页的预览状态分流、安全返回路径与参数注入、失效和临时故障分类、社交回调，以及报名/补全资料的跳转传播。另运行完整单元测试、类型检查、Lint、生产构建和现有匹配数据库回归。

部署通过 GitHub main 的既有 CI/Vercel 流程；部署后确认实际 Production 提交并重新截图。仅使用已授权测试账号查看报名成功、已保存答卷、匹配状态和通知；不为本次截图重开、重新运行或向真实用户发送通知。正常已发布详情如没有可用测试发布，不把已撤回页面或测试夹具冒充为线上已发布截图。

发布前后以只读指纹比较原问卷、手动修改面试表、原测试轮次、答卷、评分、匹配方案和通知。数据库规则与历史内容没有本次写入迁移。
