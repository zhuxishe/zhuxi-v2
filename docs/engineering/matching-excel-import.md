# 匹配轮次 Excel 追加导入

迁移：`20261023143833_matching_excel_atomic_import.sql`。本批只实施已确认的11项 A：追加更新、线上答案优先、空白保留、明确确认身份、同轮稳定临时身份、临时成员发布提示、整份回滚、请求编号防重、保留必填补充问题限制、保留旧方案并提示影响、历史身份问题只报告。

## 管理员操作与边界

- Excel 只新增报名或更新已明确选中的报名，不清空整轮，不删除或重建旧临时成员。原文件之外的报名保留。
- 姓名或昵称唯一匹配只给出建议，管理员仍需明确选择正式成员、已存在的本轮临时成员、历史成员资料或新增临时成员。重复目标、重复临时身份会在预览中报错；数据库另做一次整份校验。
- 已有答卷默认保留原值；管理员逐字段选择 Excel 后才替换。Excel 空白默认保留，只有允许为空的字段可明确清空。未涉及的兴趣、社交风格、补充答案、取消状态、答卷 ID 和创建时间保持原样；不自动恢复已取消报名。
- 临时成员仍可离线试算。没有正式绑定账号的成员无法通过原发布保护；多人池中包含临时成员时，仍可能导致整批发布被拒绝。本批不调整发布规则或算法候选资格。
- 首版继续拒绝导入含任一必填自定义补充问题的轮次，拒绝已完成匹配的轮次，不增加新的重开权限。匹配前已经开放收集的轮次仍能边收集边运行。
- 成功或失败均有导入编号与回执。同一个编号重复提交返回原回执；同一文件可经新预览、新编号再次导入，不按文件哈希永久禁止。任何身份、答卷或轮次版本冲突都要求重新预览；整份没有业务写入。
- 网络响应不明确时先查询原编号。明确终止尚无回执的编号会登记取消墓碑；之后抵达的旧请求也不会执行。成功编号的终止请求只返回原成功回执，不撤销已成功写入。
- 新导入不修改历史方案、运行输入快照、算法输出、有效匹配或通知。真实写入后回执列出既存方案编号，提醒旧方案仍使用旧输入；全部字段相同的空操作不会修改答卷时间戳，也不会把旧方案标成受影响。重新计算需要另建运行编号。
- 不自动合并、补录映射、删除或修复既往导入身份。已存在的历史临时成员可明确选中；从新版首次创建的临时身份开始建立同轮映射。跨轮不自动复用。

本批不改变重开、取消池重新分配、历史冷却或发布替换规则，也不改变原问卷、手动编辑的面试前信息表或算法评分权重。

文件上限为2 MiB，签名确认计划上限为2 MiB，差异预览序列化上限为3.5 MiB；较大文件可拆分后分别追加。Next Server Actions 使用4 MiB请求上限，低于 Vercel 当前4.5 MB请求/响应限制。文件在客户端和服务端均检查，计划超限在预览时明确拒绝。

历史例外只提示、不自动修复：兼容分0不符合现有成员主档1–5分约束，使用该历史资料新建临时成员会在预览中阻止，管理员可核对原记录或选择独立临时身份。若出现旧的已取消匹配答卷，沿用当前取消guard：保留所有字段的空操作可通过，修改内容会拒绝并保留原取消状态；不通过导入恢复报名。

## 服务端协议

浏览器只发送文件、明确选择和原因。服务端解析文件，从受限状态 RPC 读取一致的轮次、成员标记、历史资料标记和答卷版本，构造有期限的签名计划。浏览器无法修改最终成员 ID、答案、版本或临时资料后直接提交。确认时服务端验证文件哈希、计划签名、轮次、发起管理员和有效期，再把可信计划交给事务 RPC。选择历史资料时额外绑定 `expected_legacy:{id,token}`，覆盖原资料及其 canonical 成员身份摘要；历史资料变化、删除、源成员已关闭或匿名化后，不能把预览中的旧资料复制成新临时身份。

仅 `service_role` 可调用以下 public invoker 包装及 matching_import 内实现；实现再次检查真实超级管理员记录。匿名和已登录浏览器均不能直接执行，private 表启用 RLS 且不给浏览器或 service role 直接表权限。

| RPC | 用途 |
|---|---|
| `admin_preview_round_import_state(round,actor)` | 返回同一语句快照中的轮次、轮次摘要、可选成员标记、临时映射及当前答卷 |
| `admin_apply_round_import(request,round,actor,request_hash,file_sha256,reason,expected_round_token,rows)` | 原子追加更新并返回成功或安全失败回执 |
| `admin_get_round_import(request,round,actor)` | 按原编号查询回执，和正在执行的短事务互斥 |
| `admin_list_round_imports(round,actor)` | 返回回执列表，不包含原 Excel、问卷或签名计划 |
| `admin_cancel_round_import_request(request,round,actor,reason)` | 返回已有回执，或为尚无回执的编号写入取消墓碑 |

`matching_import.receipts` 保存原因、请求/文件/计划摘要、时间、安全错误码、计数和受影响方案编号，不保存姓名、答案、原文件、签名计划或临时资料。数据库额外核对计划摘要，防止相同请求哈希被误配到不同实际 RPC 内容。

`matching_import.identities` 保存 `(round_id, identity_key)` 到临时成员 UUID 的映射。key 是带来源区分的摘要，不存原姓名或历史成员 ID。同轮再次导入复用 UUID；全新导入身份不接受未经预览确认的自动归并。匿名化后仍有失效映射，硬删除后 member_id 置空保留墓碑，后续导入拒绝自动重建或重绑这些身份。

## 事务、锁与失败恢复

导入、运行输入捕获及运行完成共用 `matching-run-job:<round>` 事务级 advisory lock。导入的业务写入只能作为一个事务对外可见，因此运行捕获只能看到导入前或导入后的完整大池。算法在应用内计算期间不持有该数据库锁；导入后旧运行仍完成其原输入，不自动混入新数据。

对已存在成员及选中历史资料的 canonical 成员，先按用户 UUID 排序获取账号共享 advisory lock，再按成员 UUID 排序锁定成员；随后锁定选中的历史资料、获取成员答卷 advisory lock、锁定本轮答卷，最后锁定轮次 SHARE。这与用户保存和隐私清除的成员先行顺序相容，不先锁轮次 UPDATE 再等待成员。既有历史资料编辑使用相反的行锁顺序，因此本导入对历史资料采用 `FOR SHARE NOWAIT`：若资料正在编辑，整份安全失败并释放成员锁，避免持有成员锁等待旧编辑。新临时成员展示编号由额外前缀锁保护，稳定身份依赖 UUID 和同轮摘要映射。

执行前比较轮次结构及状态摘要、成员和身份摘要、答卷 ID 及严格递增的 updated_at。历史资料在锁定后再次比较完整源记录及 canonical 成员摘要，拒绝来源丢失、改变或已匿名化的复制；导入不修改原历史资料。事务内再次验证目的、状态、必填补充问题、目标身份和重复身份。更新只写入批准的字段；插入沿用既有数据库 guard、资料归档、成员角色和审计触发器。

回执先登记在外层事务，所有成员、身份、兴趣、统计、答卷、映射和成功审计写入放在内部保存点。任何写入或审计失败都回滚保存点，外层只提交安全失败回执；不会再用多请求补偿删除或恢复整轮。成功回执和业务写入同一事务提交。连接/进程中断使整个事务回滚时，可沿用原编号安全重试，或查询后明确终止该编号。

显式原子审计使用既有 `round_submission_import_snapshot` 类型，记录实际发起管理员、原因、变更字段和必要答卷前后值；不复制 import_metadata 内的历史资料原文。原有触发器继续执行，没有关闭审计或问卷 guard。原有匿名化及审计读取的隐私投影继续适用。
