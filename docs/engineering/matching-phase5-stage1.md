# 第5批第一阶段：资格、未匹配诊断与取消版本兼容

仅修复已复现的两处取消版本故障与人工多人检查的中间选人误报，增加运行前和失败时的资格人数、冻结输入诊断与回归覆盖。没有更改人工配对/取消池规则、重开、历史冷却、发布替换、评分、问卷或答卷。历史记录不回填、不删除；`2026秋季10月匹配（测试）` 保留。

## 实际行为

- 匹配轮次详情新增“运行前资格人数”：已保存报名、符合资格、未通过及原因分布。相同人员可能有多项原因，原因人数不能相加。调用既有 `matching_run.source`，与实际捕获的资格规则一致，仍包含本轮已有有效匹配者，不受列表分页限制。
- 这是只读预览，实际运行重新核验并冻结。读取失败显示未知、暂停新增运行，避免误报0人；原批恢复仍按冻结输入和原评分版本处理。
- 失败记录显示原批报名/合格/未通过人数及排除原因。未捕获快照时明确无人数；已脱敏快照保留捕获人数，原因标记不可用。
- 新运行以完整冻结候选池生成未匹配原因，包含已分配给其他方案的人，支持“都可以”。只有证明没有共同时间，或双人搭档为0且多人必要条件不足，才给出对应确定说明；其余显示“本次未分配，不能认定无法匹配”。大池限额搜索也明确提示未证明无解。多人候选计数是上界，不将其当成真实可行池。
- 诊断保存版本、类别及聚合人数，不保存其他成员身份、黑名单原因或互评分数。普通管理员继续不显示原始答卷和详细诊断；旧诊断不按当前资料重新猜测。
- 人工多人检查对最终完整选中池执行一次既有约束，消除中间前缀留下的误报；性别展示兼容“男/女”。没有改人工强制权限、评分或硬约束。
- 取消申请绑定发布版本及请求时间；撤回会清除当前取消字段，旧申请不能审批新版本。已取消结果恢复草稿后不再继承旧批准状态。历史通过现有私有成员审计留存，整池取消和通知规则原样。
