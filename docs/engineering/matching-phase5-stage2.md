# 第5批第二阶段：统一人工配对、取消池与结果恢复

本次只统一人工调整的资格、硬约束、现有评分和保存流程。正常新增运行仍使用完整报名大池，可在收集中运行；原正常批次快照、第一阶段修复、旧冷却/重逢、发布替换、轮次重开、导入规则、问卷和面试前信息表不变。不回填、删除或重算历史结果，保留 `2026秋季10月匹配（测试）`。

## 八项行为

1. 人工配对与取消池复用正常候选资格，包括既有合法导入例外；超级管理员也不能强制绕过硬约束。最终整组选人检查共同时间、人数偏好、性别、黑名单、旧冷却及禁忌，取消新手硬限制的既定行为不变。
2. 取消池只包含当前方案已取消结果的成员，并扣除当前方案已有有效结果的成员；不自动吸收未匹配、后来报名或其他方案成员。人工选人可使用本轮后来合格的报名者。
3. 取消结果和拆分结果不等于撤销报名，保留原报名。原整池成员，包括申请取消的人，在报名仍有效且符合资格时可以重新参与。
4. 每次人工配对、取消池、恢复或拆分拥有独立操作编号、原因和记录。新评分操作捕获当时有效资料、已发布人格配置和有效活动互评；恢复同编号使用冻结引擎，不能偷偷刷新资料。正常批次快照不变。
5. 人工和取消池沿用现有 v3 100 分权重、人格维度权重、活动互评及历史处理。多人记录真实均分及分布，不再写假零分。原历史结果不重算。
6. 同一方案最多一个有效多人池，无六人上限。已有池保持原样，取消池可生成双人结果，多人限定成员不能被强行转成双人；新增多人池需明确拆分旧池后重新组建，不自动合并。
7. 取消池显示范围人数、合格人数、排除人数与原因；排除者记录保留。合格余下成员继续参与，少于二人明确停止。读取失败显示未知；隐私清理后保留人数并说明原因不可用。
8. 恢复已取消结果重新检查当前资格、占用、硬约束及原推荐时间，保留原结果分数、评分明细与时间。这里是恢复结果，不是轮次重开。

## 操作与保存

新 `matching_adjustment` 私有 schema 保存操作、范围、独立输入、冻结引擎、原结果和被替换诊断。表无浏览器访问策略或直接服务端表授权；public RPC 是仅 service role 可执行的 invoker wrapper，内部 definer 校验实际后台管理员。普通管理员只获得安全摘要，不获得原始快照、审计操作者或评分明细。

每方案最多一个运行中调整；操作编号校验方案、发起人、种类、目标和成员集合。五分钟租约、原编号恢复和成功回执处理重复请求、超时与丢失响应。失败不删除旧方案、旧结果或原始快照；已知不可恢复输入须明确重新检查并开始新操作，不自动换编号。

保存事务再次核验方案仍为完整草稿、版本未变、当前资格/占用、单一多人池、名单分区和诊断结构，并检查所选成员的硬约束输入是否变化。无关的新报名、后来发布人格配置或新活动互评不会使冻结重试失效；所选可用时间、偏好、禁忌或旧硬关系变化则要求新操作。结果、诊断、人数和成功回执原子提交。锁定/解锁、原发布与整池取消继续原路径；浏览器直接写名单、分数、拆分、恢复或诊断不能绕过新入口。

隐私清理触发器清除涉及成员的调整原始输入、引擎、原结果和诊断归档，保留无原始资料的操作计数。不会重新开放匿名化成员的资格。结果卡片资料区明确提示“原批资料摘要；人工调整以对应操作快照为准”，它不是独立调整快照查看器。
