# 匹配报名资料完成检查

本次只增加“收集时间后匹配”活动的报名门槛，不改匹配算法、权重、问卷题目或必填配置。网页端覆盖电脑、手机浏览器及 LINE 内网页；微信小程序不新增提示和补填界面，但其直接提交仍受数据库检查约束。

## 完成标准

报名仍要求登录、审核通过、账号有效且具有玩家身份。额外检查仅包含“补充资料”“性格自评”“性格测试”，个人中心的完成标记使用同一规则。

- 按成员已绑定的问卷版本检查启用的必填题，必须有有效提交。发布新版不取消旧版完成资格，不强迫老用户回答新增题。
- 历史答卷满足原版本要求就认可；尚未绑定版本时使用可信旧基线，不套用最新发布版。不能仅凭存在一行数据或自动迁移生成的完成标记放行；旧默认值不等于用户完成填写。
- 选填题可留空。当前“补充资料”默认 19 题全部选填，零必填题时空白成功提交也算完成，从未提交则不算。旧模式保存使用服务器完成凭据，版本化提交明确记录完成；读取检查本身不保存答案、不新建答卷、不切换版本。
- 性格测试主动重测时，上一次有效完成结果仍提供报名资格；未提交的新测试不撤销该资格。存在旧结果但其必填答案不完整时，报名补填入口直接打开答题页。

## 报名及补填流程

仅 `match_rounds.purpose = 'matching'` 的新报名、取消后重新报名和修改报名需要检查，现有开放活动及后续活动均适用。固定时间报名、活动通知、取消报名和服务器历史导入保持原有行为；未完成资料不会删除或作废已有报名。

入口点击先检查。未完成时列出缺项，提供“去完善”“取消”；取消关闭提示并留在原入口。直接访问问卷 URL 仍会拦截，取消返回对应参与记录或首页。读取失败显示重试，不能伪装成未完成或直接放行。

“去完善”进入 `/app/profile/complete`，按以下固定顺序推进，每次保存成功都重新读取服务器状态：

1. 补充资料。
2. 性格自评。
3. 性格测试。
4. 返回原活动的匹配问卷，由用户继续填写和提交，不自动报名。

已完成项目自动跳过；重新打开旧步骤链接不能倒退到已完成项目或跳过较早缺项。每份成功提交的结果独立保留，保存失败保留当前页面答案。补填期间活动截止后，资料仍保留，返回活动时显示截止状态。

返回参数只接受严格 UUID 的轮次 ID 和固定 `from=participation` 来源。推进页用 `round`，问卷页用 `matchingRound`；不接收任意返回 URL。独立从“我的”打开问卷不进入连续补填流程，保留原返回方式。

当前问卷不增加自动草稿保存。答案变更后，页面内链接和显式离开按钮先确认；浏览器支持时，刷新、关闭及同文档历史导航也提供提醒。成功提交清除提醒。浏览器自身限制可能阻止关闭提示，不承诺跨浏览器强制拦截。不支持 Navigation API 时，通知等通过按钮直接调用程序跳转的入口不受链接离开提醒保护；本次没有改造全局通知导航。

## 后台与数据库约束

管理员代报名、修改匹配报名同样检查三项资料，没有人工跳过按钮。玩家提交和管理员写入均由数据库触发器再次校验，因此直接调用接口或绕过页面也无法放行。

历史导入及其补偿操作使用既有服务器 `service_role` 路径豁免；前端参数、导入元数据、成员来源字段或自行设置 JWT/GUC 文本不能获得豁免。用户取消与账号匿名化清理仍可执行。数据库会在报名校验与问卷保存之间使用成员行锁，避免校验和写入之间出现状态竞争。

## 发布顺序与验证

增量迁移：`supabase/migrations/20261022162627_matching_profile_readiness.sql`，依赖已有问卷版本迁移 `20261021110438_questionnaire_templates_versions.sql` 及成员主档相关迁移。

**先应用并验证数据库迁移，再部署应用。** 新页面依赖完成状态 RPC；迁移缺失或 RPC 失败时会阻止匹配报名并提示重试。核对目标数据库与已登记迁移后，在隔离工作区只应用这条新增迁移，不用 `--include-all` 重放历史迁移。迁移不发布新问卷、不改写历史答卷、不自动报名；回退应用不应删除问卷历史或完成凭据。

```sh
pnpm typecheck
pnpm lint
pnpm test:unit
pnpm build
PGLITE_MODULE=/absolute/path/to/@electric-sql/pglite/dist/index.js node supabase/audits/matching-profile-readiness-pglite.mjs
```

PGlite 是独立验证依赖，审计脚本只使用隔离内存数据库，不连接正式环境。它执行真实迁移及成员/问卷 RPC，验证旧版本、历史空默认值、显式空提交、必填验证、重测资格、状态摘要、玩家与管理员拦截、直接写入防绕过、历史导入、取消、匿名化和非匹配活动。

应用测试覆盖入口弹窗、直接 URL 拦截、读取失败、三项依次补填、返回相同轮次、保存失败保留答案和未保存提醒。上线核对数据库的两个公开 RPC（`get_my_matching_readiness`、`get_member_matching_readiness`）、`matching_profile_readiness_guard` 触发器及权限；再用测试账号验证报名拦截、补填返回和管理员代报名，不用真实用户答卷做破坏性测试。
