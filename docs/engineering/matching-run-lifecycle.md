# 匹配运行编号、批次与失败恢复

迁移：`20261023112514_matching_run_lifecycle.sql`。仅新增 `matching_run.jobs/events` 和受限 RPC，既有候选资格、算法、问卷、收集时间、重开、导入、取消池及发布保护不变。

## 操作与输入

- 轮次内每次明确新运行有递增批次号，UUID 同时是请求幂等编号。浏览器只在 sessionStorage 保存该编号，不存问卷、理由或个人资料。请求失败及刷新后重试沿用原编号；成功或明确作废后才开始新编号。
- 同一轮只允许一个处理中的任务。登记与数据库写入使用短事务锁，计算期间没有数据库锁，报名仍可继续提交。新运行继续捕获完整报名大池，不排除本轮已有有效匹配者。
- 成功回执优先于当前轮次状态校验；closed 成功转 matched 后重试仍返回原方案，不会重新计算。主动新运行仍遵守原 open/closed 规则，不新增 matched 重跑或重开权限。
- 初次捕获原答卷、资格及历史；计算前保存准确 engine input。恢复已准备任务直接使用原 engine input；未准备任务只使用原 source，算法/适配器版本不兼容时拒绝恢复。
- 原方案不因新增运行删除，也不继承旧方案的人工配对或锁定。原“重新匹配”按钮改为保留方案、返回轮次详情。显式删除草稿仍沿用现有接口；成功任务保留历史回执，原编号不会复活已删方案。

## 完成与异常

- `begin` 原子登记和捕获；`stage` 保存原 engine input；`complete` 在一个事务内创建 session、封存输入、保存全部结果和诊断、核对原收集状态与日期、设置 results_ready，并保存成功回执。任何写入故障使整个完成事务回滚。
- 服务端计算或数据库报错后先查询回执；不能把网络错误直接当失败删除会话。失败记录仅存固定安全错误码和提示。`fail` 遇到已成功任务只返回成功，不降级或删除。
- 任务租约为5分钟。未到期只返回处理中；过期后发起管理员可恢复，换发 token，旧执行者不能再保存。没有后台自动重算、定时轮询或自动清理。
- 捕获失败没有可复用原输入；原候选不足2人也不能靠恢复读取新报名。两者保留失败记录，须作废后新增运行。原状态或收集日期变动、输入隐私清除、版本不兼容时也不能冒充原任务恢复。
- 发起管理员可恢复或作废已失败/过期任务；超级管理员可审计作废其他人的已失败/过期任务，避免失联发起人阻塞全轮。任何人都不能作废成功任务或租约未过期的任务。作废不删除已有方案或原输入，理由记录到 events。

## 权限与发布

表启用 RLS，无浏览器或 service-role 直接表权限。服务 RPC 要求 service role 加真实有效管理员；浏览器只能通过管理员 RPC 列出安全元数据和按权限作废。原输入和 lease token 不返回客户端。原有成员匿名化触发器继续清除快照原文和 engine input，恢复不能重建已清除资料。

本轮未改变现有发布、撤回、同轮每人一份有效匹配及通知规则。计算完成不会自动发布或通知。旧方案中的成员与新方案重叠时，发布仍按原规则整批拒绝冲突。

## 验证与发布

`matching-run-lifecycle-pglite.mjs` 复用真实迁移隔离 schema，先执行原192项输入快照检查，再检查幂等、过期恢复、输出分区、13人池、零覆盖、权限、隐私、实际写入故障回滚及无通知副作用。单元测试另验证网络响应丢失后查询回执、跨轮 UUID 误用拒绝、原输入恢复及浏览器编号持久化。

生产先记录业务/问卷/通知指纹和数据库 advisors；从独立发布目录 dry-run 仅本迁移，再应用并核对原函数定义未变、新 RPC ACL、表权限及业务指纹。随后推送已验证的 main，核对 CI、Vercel Ready 和正式后台入口。生产验证不运行真实匹配或发通知。
