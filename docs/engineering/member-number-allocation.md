# 会员编号自动分配

沿用 `members.member_number` 与现有用户/后台页面。首次非空姓名资料成功保存时在后台预占，面试通过时复用编号；注册、审核 UI 不变，无认领提示。只在 `/app` 问候下增加已有会员编号。后台手动改号仅失败显示错误，成功不新增提示。

## 规则

- DOCX 2026-10-06 编号名单由数据库私有函数常量保存：001–247 为线下名单预留，000 为官方特殊号。不创建这些人的成员或 Auth 账号，不新增编号登记表。
- 姓名精确匹配名单，编号按名单；吴璠对应 `ZXS_081`。保留现有官方 `ZXS_000`，不把姓名“竹溪社”改成名单文字“竹溪社官方”。
- 未匹配者从 248 和历史最高已发号之后顺序分配；资料首次登记的成功事务决定预占顺序。复填、改名、重复审核不重新发号，人工调整保留。
- sequence 保存只升不降的高水位，失败事务可能留下空号，不保证连续；现有审计 metadata 保存编号使用/退役。停用、注销、匿名化及改号后的旧编号不自动复用，手动改号同样不得占用他人、预留或退役号。
- 编号统一为 `ZXS_` 加至少三位数字；1000 以上自然扩展，不截断。沿用内部 UUID 关联业务。历史/临时 `IMP-` 档案不转换、不绑定账号。
- 当前成员回填优先依据既有姓名步骤审计；缺少该依据时只能使用身份档案创建时间等历史近似排序，不声称恢复了原始注册顺序。后续注册均按首次姓名成功登记顺序执行。
- 数据库统一保护直接写入、单人/批量审核、高级账号编辑、审计恢复与匿名化路径。已有超级管理员改号权限保持不变。

## 验证与发布

新增迁移 `20261006111856_member_number_allocation.sql`。运行 `pnpm test:unit`、`pnpm typecheck`、`pnpm lint`、`pnpm build`，并使用 `PGLITE_MODULE=/path/to/@electric-sql/pglite/dist/index.js node supabase/audits/member-number-allocation-pglite.mjs` 验证真实 SQL；PGlite 单连接不代表正式库多连接压力测试。

先保存正式库现有编号与姓名对应的最小快照，核对现有官方号、名单占用与历史档案。只从临时发布目录 fetch 正式库迁移历史，复制本次唯一增量，dry-run 确认只待执行该文件后应用；禁止从主工作区 `db push --include-all`。数据库校正、权限、高水位及审计 postflight 通过后再推送应用。上线期间不创建正式库测试玩家、不更改历史成员身份。

代码回退不会撤销已发号、校正数据或 sequence。失败时保留审计与编号历史，采用受控前向修复；不删除审计、不倒退计数器。

## 本次发布的数据冲突

2026-10-06 正式库首次应用在不可复用校验处拒绝，完整事务回滚；192 个成员原编号均未变化。真实编号审计已补入隔离验证，避免仅使用成员快照漏掉已用编号。

官方账号的审计 1333/1334 显示当日曾误填 `ZXS_001`，三分钟后改为 `ZXS_000`，而线下名单将 001 分配给陈风。本迁移包含可审查的一次性纠错草案：只有两个已核验账号、两条审计的来源/动作/时间/编号流转、账号状态和全库规范化占用均符合预检证据时，才校正这一条成员记录，并追加纠错依据；原审计不改。任何额外号主、退役事件、关闭/匿名账号或证据变化均拒绝并整事务回滚。纠错完成后全部编号保护触发器必须启用，不留下日常改号旁路。

正式应用这个纠错草案仍需用户决定是否将上述两条记录视作旧编号误填；截至本次准备结束，正式迁移与正式应用发布尚未完成。
