# 会员编号自动分配

沿用 `members.member_number` 与现有用户/后台页面。首次非空姓名资料成功保存时在后台预占，面试通过时复用编号；注册、审核 UI 不变，无认领提示。只在 `/app` 问候下增加已有会员编号。后台手动改号仅失败显示错误，成功不新增提示。

## 规则

- DOCX 2026-10-06 编号名单由数据库私有函数常量保存：001–247 为线下名单预留，000 为官方特殊号。不创建这些人的成员或 Auth 账号，不新增编号登记表。
- 姓名比较键忽略任意位置的半角 U+0020、全角 U+3000 空格，再精确匹配名单；姓名原文、其他字形和标点保持，规范化后有重名则拒绝自动发号。编号按名单，吴璠对应 `ZXS_081`。保留现有官方 `ZXS_000`，不把姓名“竹溪社”改成名单文字“竹溪社官方”。
- 未匹配者从 248 和历史最高已发号之后顺序分配；资料首次登记的成功事务决定预占顺序。复填、改名、重复审核不重新发号，人工调整保留。
- sequence 保存只升不降的高水位，失败事务可能留下空号，不保证连续；现有审计 metadata 保存编号使用/退役。停用、注销、匿名化及改号后的旧编号不自动复用，手动改号同样不得占用他人、预留或退役号。
- 唯一回收例外为 2026-10-12 已核验的 `ZXS_257`–`ZXS_261`：257/258 从未发出，259–261 由本次纠错释放。优先按数值领取这组有限空号，再从原高水位接续；每号只能领取一次，成功领取后的任何停用、注销或改号都不重新开放。原审计和 sequence 不倒退，真实退役的 248 及所有其他历史编号仍不可复用。
- 编号统一为 `ZXS_` 加至少三位数字；1000 以上自然扩展，不截断。沿用内部 UUID 关联业务。历史/临时 `IMP-` 档案不转换、不绑定账号。
- 当前成员回填优先依据既有姓名步骤审计；缺少该依据时只能使用身份档案创建时间等历史近似排序，不声称恢复了原始注册顺序。后续注册均按首次姓名成功登记顺序执行。
- 数据库统一保护直接写入、单人/批量审核、高级账号编辑、审计恢复与匿名化路径。已有超级管理员改号权限保持不变。
