# 活动结束后的报名评分要求

本功能于 2026-11-05 完成本地验证及 Production 数据库迁移，应用随本次主分支提交发布。新增迁移为 `20261105095725_registration_review_gate.sql`，不改写既有报名、评分或匹配结果。

## 业务规则

每次新增报名或取消后重新报名，逐场检查本人参加过的已结束活动。所有仍需评分的活动均完成或获免除后才可继续报名；不以“最近一次报名”“最近一次评价”判断，也不要求对方先评价本人。

| 条件 | 处理 |
| --- | --- |
| 收集时间后匹配 | 本场给任意一位搭档／同组成员提交评分即完成 |
| 固定时间活动报名 | 本场给至少一位实际交流过的参与者提交评分即完成 |
| 文字评价 | 选填；继续沿用两类评价各自的评分字段 |
| 单独举报 | 不算完成评分；可由管理员核实后免除 |
| 尚未结束 | 不产生报名限制，允许重叠活动提前报名 |
| 已完成评分 | 不受其他人是否评分影响；已有评分直接计入，后续标记无效不自动撤销提交完成状态 |
| 正常评价截止 | 未完成者仍可补交一份评分；成功后不可继续利用补评入口新增或修改评分 |
| 未开放或主动暂停评价 | 暂不限制报名；恢复可提交后再次检查 |
| 确认没有评价对象 | 当前不限制，且不写入永久免除；以后有真实对象时重新判断 |
| 未赴约等特殊情况 | 管理员按成员、活动记录免除及理由；撤销后重新按当前状态判断 |
| 已成功报名 | 保留资格；编辑、取消、查看不受本项限制 |

匹配活动的 `activity_end` 包含结束日全天，使用 `Asia/Tokyo` 次日 00:00 作为结束边界。11 月 4–17 日这场的边界是 **2026-11-18 00:00 日本时间**。固定活动使用 `content_config.eventEnd` 的具体时刻。报名 `survey_end` 不参与活动结束判断。

例如 A 为 11 月 1–17 日，B 为 11 月 14 日：A 未结束时可以报名 B；B 先结束后只检查 B。B 先评过不会清除之后结束的 A，A 先评过也不会清除 B。两场结束后若均未评分，弹窗同时列出两场。管理员只免除 A 时，B 仍需处理。

## 纳入范围

范围保存在私有表 `private.round_review_requirements`，以活动 UUID 关联。迁移只通过“正式非测试、未删除、用途 matching、名称 `竹溪社11月匹配活动`、日期 2026-11-04 至 2026-11-17”定位这场既有活动，不使用宽泛日期阈值。匹配多条会中止迁移；部署前必须核实恰好一条并记录其 UUID。空的隔离环境可以无历史记录，线上不得把零命中当成验收成功。

其余已有发布／参与历史的活动快照为不纳入，重新开放不会追溯旧活动。新活动首次开放自动纳入。迁移时仍是草稿、没有报名、匹配、参与名册、评分或举报历史的活动，保留首次发布待纳入状态；单纯提前配置或启用空名册的互评不算发布历史。测试活动不产生正式活动评分义务。

匹配活动只使用当前正式发布、未撤回的 publication、有效 assignment、matched roster 和一致版本的结果生成评价链接。尚未发布、撤回或无匹配对象时，不生成无法完成的报名要求。

## 报名、评价和后台入口

- 玩家点击报名时提前检查并弹窗；直接进入报名 URL 也检查。提交时再次检查，数据库 `BEFORE INSERT / UPDATE OF cancelled_at` 触发器为最终约束，覆盖直接 API 和重新报名。
- 已有效报名的编辑入口跳过新增门槛，即使评价查询不可用也不误挡编辑；真正新增报名遇到读取错误显示重试，不把错误解释为没有欠评。
- 两类评价继续使用各自数据：匹配走 `mutual_reviews`，固定活动走 `round_peer_reviews`。单独举报不会满足评分要求。
- 匹配搭档评价沿用已发布结果入口，其原有流程没有固定活动互评的截止窗口。新增的截止后补评仅扩展固定活动；匹配轮次的泛活动互评不能代替搭档评分解除报名门槛。
- `returnRound` 只接受单个 UUID。评价搜索、分页和多人选择保留返回目标，返回时只重建内部报名 URL，不接受任意跳转地址，不自动提交报名。
- 补评成功后立即停止该场额外补评，保留举报功能；返回报名时再次检查其他活动。正常评价窗口内的既有编辑规则不变。
- 报名表单遇到拦截后取消弹窗或重新检查会保留当前输入。离页去评价仍沿用既有表单生命周期，未新增跨页持久化草稿。
- 后台“活动互评”新增“报名评分要求”，可按姓名／昵称检索，逐人逐场免除或撤销。必须填写理由并携带版本；冲突、网络失败保留输入。
- 既有管理员实际到场补录、恢复取消报名及导入权限继续使用原授权判断，不能仅凭玩家传入的标志绕过。

公开 API：`player_get_registration_review_gate`、`admin_get_round_review_requirements`、`admin_set_round_review_exemption`。身份由当前会话派生。实现函数位于非 API schema `registration_review_gate`；私有表启用 RLS 且无普通玩家直接读写权限。免除与撤销保留审计，并纳入成员生命周期预检和匿名化清理。
